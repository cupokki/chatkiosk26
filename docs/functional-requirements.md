# MVP 기능 요구사항 (Functional Requirements)

## 1. 목적과 범위

본 문서는 **AI 키오스크 기반 스마트 주문 및 관리 시스템(MVP)**의 기능 요구사항을 사용자 흐름, 비즈니스 규칙, 예외 흐름 및 완료 조건 중심으로 정의함.
본 문서는 `docs/use-cases.md`(유즈케이스 명세서)의 사용자와 시스템 간 상호작용 흐름을 바탕으로 작성되었으며, 백엔드 API 설계, 프론트엔드 UI 개발 및 테스트의 기준 문서로 활용됨.

### 포함 범위

- 고객: 메뉴 탐색 및 필터링, 대화형/수동 장바구니 조작, 주문 완료 및 결제 스텁
- 관리자: 메뉴 등록/수정/소프트 딜리트, 동적 메뉴 검색(QueryDSL), 판매 통계 조회(Recharts)

### 제외 범위

- 회원가입·로그인·권한 관리
- 실제 PG 결제·환불
- 재고·쿠폰·포인트·이미지 업로드·다점포 관리
- TTS·STT

## 3. 고객 기능 요구사항 (Customer Requirements)

### FR-C01. 메뉴 탐색 및 필터링 (UC-C01 매핑)

- **FR-C01-1 (판매 가능 메뉴 목록 조회)**: 고객에게 판매 중지(`available = false`)나 삭제(`deletedAt IS NOT NULL`)되지 않은 메뉴 목록을 카테고리별로 조회하여 표시함.
- **FR-C01-2 (카테고리 필터링)**: 고객이 특정 카테고리를 선택하면 해당 카테고리에 속한 메뉴만 필터링하여 제공함.
- **FR-C01-3 (메뉴 없음 안내)**: 선택한 카테고리에 등록된 메뉴가 없거나 모든 메뉴가 비활성화된 경우 "해당 카테고리에 등록된 메뉴가 없습니다." 안내 메시지를 표시함.

### FR-C02. 대화형 장바구니 조작 (UC-C02 매핑)

- **FR-C02-1 (자연어 의도 분석)**: 대화 입력 창의 자연어 입력, 현재 장바구니 상태, 판매 가능 메뉴 목록, 대화 맥락을 LangChain(LLM)에 전달하여 구조화된 액션(`ADD`, `REMOVE`, `CHANGE_QUANTITY`) JSON으로 변환함.
- **FR-C02-2 (액션 검증 및 반영)**: 변환된 액션 중 메뉴 존재 여부와 판매 가능 여부(`available = true`, `deletedAt IS NULL`)를 검증하고, 유효한 액션만 장바구니에 반영함.
- **FR-C02-3 (대화 응답 반환)**: 장바구니 반영 결과(성공 항목 및 거절된 항목의 사유)를 대화창 응답으로 반환함.
- **FR-C02-4 (LLM/파싱 오류 처리)**: LLM 호출 실패 또는 JSON 파싱 오류 발생 시 장바구니를 변경하지 않고 유지하며, "죄송합니다. 요청을 이해하지 못했습니다. 다시 말씀해 주시거나 화면에서 직접 선택해 주세요." 안내 메시지를 응답함.
- **FR-C02-5 (주문 불가 메뉴 요청 처리)**: 존재하지 않거나 판매 중단된 메뉴 요청 시 해당 액션만 거부하고 "현재 'XXX' 메뉴는 주문할 수 없습니다." 사유를 안내하며, 다른 유효 액션은 정상 반영함.
- **FR-C02-6 (수량 제약)**: 수량 변경 요청 시 변경 후 수량이 0 이하가 되면 해당 항목을 장바구니에서 제거하거나 경고 메시지를 제공함.

### FR-C03. 수동 장바구니 조작 (UC-C03 매핑)

- **FR-C03-1 (UI 직접 조작)**: 메뉴 카드의 [담기] 버튼 및 장바구니 목록의 수량 조절(+, -), [삭제] 버튼을 통해 장바구니를 직접 변경할 수 있음.
- **FR-C03-2 (유효성 확인 및 금액 계산)**: 항목 추가/변경 시 메뉴의 판매 상태 및 소프트 딜리트 여부를 검증하고, 소계 및 총 결제 금액을 실시간으로 계산하여 UI를 갱신함.
- **FR-C03-3 (최소 수량 처리)**: 수량이 1인 상태에서 (-) 버튼 클릭 시 항목 삭제 확인 팝업을 띄우거나 삭제 처리함.

### FR-C04. 주문 완료 및 결제 (UC-C04 매핑)

- **FR-C04-1 (주문 생성 전 검증)**: [주문하기] 클릭 시 장바구니 내 모든 메뉴의 현재 판매 가능 여부(`available = true`, `deletedAt IS NULL`)를 재검증함.
- **FR-C04-2 (주문 스냅샷 저장)**: 주문 생성 시점의 메뉴명과 단가(`unitPrice`)를 포함하여 `OrderItem` 스냅샷을 생성하고, 주문 상태를 `COMPLETED`로 저장함.
- **FR-C04-3 (결제 스텁 처리)**: PG 연동 대신 결제를 항상 즉시 승인하는 성공 스텁으로 처리함.
- **FR-C04-4 (장바구니 초기화 및 안내)**: 주문 완료 후 장바구니를 초기화하고, 생성된 주문 번호와 주문 완료 화면을 표시함.
- **FR-C04-5 (빈 장바구니 예외)**: 장바구니가 비어 있는 경우 [주문하기] 버튼을 비활성화하거나 클릭 시 "장바구니가 비어 있습니다." 알림을 띄움.
- **FR-C04-6 (품절/삭제 메뉴 예외)**: 주문 검증 시 판매 중단/삭제된 메뉴가 포함된 경우 주문 생성을 거부하고 "장바구니에 판매가 중지된 메뉴(XXX)가 포함되어 있어 주문할 수 없습니다." 안내 및 해당 메뉴 삭제를 유도함.

## 4. 관리자 기능 요구사항 (Admin Requirements)

### FR-A01. 메뉴 관리 (UC-A01, UC-A02, UC-A03 매핑)

- **FR-A01-1 (메뉴 등록)**: 메뉴명, 가격, 카테고리, 설명, 태그, 판매 여부(`available`)를 입력받아 등록함. 필수 값 누락 또는 가격이 0원 미만인 경우 에러 메시지를 표시하고 저장을 거부함.
- **FR-A01-2 (메뉴 수정 및 상태 변경)**: 등록된 메뉴의 기본 정보 및 판매 상태(`available`)를 수정할 수 있음. 상태 변경 결과는 고객 메뉴 목록에 즉시 반영됨.
- **FR-A01-3 (소프트 딜리트)**: 메뉴 삭제 요청 시 DB에서 물리적으로 삭제하지 않고 `deletedAt` 필드에 삭제 시각을 기록(Soft Delete)함.
- **FR-A01-4 (스냅샷 보존)**: 소프트 딜리트되거나 판매 상태가 변경된 메뉴라도 이미 생성된 과거 주문 기록 및 주문 항목(`OrderItem`)의 메뉴명/단가 스냅샷은 영향을 받지 않고 유지됨.

### FR-A02. 동적 메뉴 검색 (UC-A04 매핑)

- **FR-A02-1 (QueryDSL 동적 쿼리)**: 키워드(메뉴명/설명), 카테고리, 판매 여부(`available`), 최소 가격, 최대 가격 조건의 조합으로 메뉴를 검색함.
- **FR-A02-2 (조건 생략 처리)**: 입력되지 않은 검색 조건은 쿼리 대상에서 자동으로 제외함. 조건이 없으면 전체 메뉴를 조회함.
- **FR-A02-3 (페이징 제공)**: 검색 결과는 지정된 페이지 사이즈 기반의 페이징 목록으로 제공함.

### FR-A03. 판매 통계 조회 (UC-A05 매핑)

- **FR-A03-1 (통계 필터링)**: 주문 기간(시작일~종료일), 카테고리, 가격 구간 조건으로 통계를 필터링함.
- **FR-A03-2 (집계 기준)**: 주문 상태가 `COMPLETED`인 주문만 집계 대상에 포함하며, 집계 금액은 주문 시점의 `OrderItem.unitPrice` 스냅샷과 수량을 기준으로 계산함.
- **FR-A03-3 (통계 제공 항목)**: 총 매출액, 총 판매 수량, 인기 메뉴 Top 5 목록을 표 및 차트(Recharts) 형태로 제공함.

## 7. 완료 기준 (Acceptance Criteria)

- 고객은 카테고리 탐색, 대화형(자연어) 조작, 수동 버튼 조작으로 장바구니를 변경하고, 검증 실패 없이 주문을 완료할 수 있음.
- 존재하지 않거나 판매 중단/삭제된 메뉴는 장바구니 추가 및 주문이 차단되고 명확한 에러 메시지가 표시됨.
- 관리자는 메뉴 등록·수정·소프트 딜리트를 수행하고, QueryDSL 기반 동적 조회를 수행할 수 있음.
- 관리자는 완료(`COMPLETED`)된 주문의 스냅샷 데이터를 기반으로 기간/카테고리별 총 매출액, 판매 수량, 인기 메뉴 Top 5 통계를 확인할 수 있음.
