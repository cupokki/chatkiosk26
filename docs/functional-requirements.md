# MVP 기능 요구사항

## 1. 목적과 범위

AI 키오스크 기반 스마트 주문 및 관리 시스템의 MVP 기능을 사용자 흐름, 비즈니스 규칙, 완료 조건 중심으로 정의한다. 이 문서는 구현·API 설계·테스트의 기준 문서다.

### 포함 범위

- 고객의 메뉴 탐색, 대화형 장바구니 조작, 주문 완료
- 관리자의 메뉴 관리, 복합 조건 메뉴 검색, 판매 통계 조회

### 제외 범위

- 회원가입·로그인·권한 관리
- 실제 PG 결제·환불
- 재고·쿠폰·포인트·이미지 업로드·다점포 관리
- TTS·STT

## 2. 사용자와 핵심 흐름

| 사용자 | 목표 | 핵심 흐름 |
| --- | --- | --- |
| 고객 | 대화로 장바구니를 구성하고 주문한다. | 메뉴 탐색 또는 대화 입력 → 장바구니 반영 → 주문 완료 |
| 관리자 | 메뉴를 관리하고 판매 현황을 파악한다. | 메뉴 관리 또는 복합 검색 → 기간별 판매 통계 확인 |

## 3. 고객 기능 요구사항

### FR-C01. 메뉴 탐색

- 고객은 판매 가능한 메뉴 목록을 조회할 수 있다.
- 고객은 카테고리로 메뉴 목록을 필터링할 수 있다.
- 판매 중지 또는 삭제된 메뉴는 고객 목록에 표시하지 않는다.

### FR-C02. 대화형 장바구니 조작

- 고객은 화면의 대화형 창에서 자연어로 장바구니 조작을 요청할 수 있다.
- 시스템은 LangChain을 통해 대화 맥락, 현재 장바구니, 판매 가능한 메뉴 정보를 분석한다.
- 시스템은 장바구니 항목의 추가, 제거, 수량 변경 요청을 구조화된 작업으로 변환한다.
- 시스템은 메뉴 존재 여부와 판매 여부를 검증한 뒤, 유효한 작업만 장바구니에 반영한다.
- 시스템은 반영 결과와 불가한 작업의 사유를 대화형 응답으로 반환한다.
- LLM 호출 또는 작업 파싱에 실패하면 장바구니를 변경하지 않고 재입력 안내를 보여 준다.
- 대화 기능이 실패해도 고객은 메뉴 목록에서 장바구니를 직접 조작할 수 있어야 한다.

### FR-C03. 장바구니

- 고객은 메뉴를 장바구니에 추가·삭제할 수 있다.
- 고객은 메뉴별 수량을 변경할 수 있으며 수량은 1 이상이어야 한다.
- 시스템은 각 항목 금액과 전체 합계를 표시한다.
- 대화형 기능이 수행한 장바구니 변경도 동일한 수량·메뉴 검증 규칙을 적용한다.

### FR-C04. 주문 완료

- 고객은 장바구니 항목으로 주문을 생성할 수 있다.
- 시스템은 주문 시점의 메뉴명과 단가를 주문 항목에 저장한다.
- 시스템은 결제를 항상 성공하는 스텁으로 처리하고 주문 상태를 `COMPLETED`로 저장한다.
- 존재하지 않거나 판매 중지된 메뉴를 주문하려 하면 주문을 거절하고 사유를 안내한다.

## 4. 관리자 기능 요구사항

### FR-A01. 메뉴 관리

- 관리자는 메뉴를 등록·수정·삭제할 수 있다.
- 관리자는 메뉴의 판매 여부를 변경할 수 있다.
- 메뉴는 이름, 가격, 설명, 태그, 카테고리, 판매 여부를 가진다.
- 메뉴·카테고리·주문·주문 항목의 삭제는 모두 소프트 딜리트로 처리한다.
- 소프트 딜리트된 데이터는 일반 조회와 통계 대상에서 제외한다. 단, 기존 주문의 메뉴명·단가 스냅샷은 보존한다.

### FR-A02. 동적 메뉴 검색

- 관리자는 키워드, 카테고리, 판매 여부, 최소 가격, 최대 가격을 조합해 메뉴를 검색할 수 있다.
- 입력하지 않은 조건은 검색 조건에 적용하지 않는다.
- 검색 결과는 페이징된 목록으로 제공한다.

### FR-A03. 판매 통계

- 관리자는 주문 기간, 카테고리, 가격 구간으로 판매 통계를 필터링할 수 있다.
- 시스템은 매출 합계, 판매 수량, 인기 메뉴 Top 5를 제공한다.
- 통계에는 주문 상태가 `COMPLETED`인 주문만 포함한다.
- 금액 집계는 주문 시점의 `OrderItem.unitPrice`와 수량을 기준으로 한다.

## 5. 핵심 정책과 미결 결정

| 항목 | MVP 기본 정책 | 확정 필요 사항 |
| --- | --- | --- |
| 삭제 | 모든 엔티티 삭제는 소프트 딜리트로 처리한다. | 삭제 상태를 나타낼 필드와 복구 필요 여부 |
| 대화형 장바구니 | LLM은 맥락을 분석하고 구조화된 작업만 반환한다. | 대화 세션 유지 방식과 허용 작업 형식 |
| 가격 구간 통계 | 주문 당시 단가 기준 | 구간 경계 포함 규칙 |
| 주문 기간 | 시작일·종료일 필터 | 시간대와 종료 시각 포함 규칙 |

## 6. 완료 기준

- 고객이 대화형 창 또는 메뉴 탐색으로 장바구니 항목을 추가·제거·수정하고 주문을 완료할 수 있다.
- 관리자가 복합 조건으로 메뉴를 검색하고, 완료 주문 기준의 판매 통계를 조회할 수 있다.
- 각 기능의 API 요청·응답 및 오류 형식은 구현 전에 별도 API 계약 문서에서 확정한다.
